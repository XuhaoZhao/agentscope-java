⏺ 现在完整的链路已经清晰了，下面是总结：

  ---
  大模型如何表达"我要用工具"

  大模型并不直接返回 ToolUseBlock Java 对象。它返回的是特定于各厂商的 JSON 响应格式，框架通过 ResponseParser 将其转换。

  以两个主流厂商为例：

  OpenAI 格式（OpenAIResponseParser）

  {
    "choices": [{
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [{
          "id": "call_abc123",
          "type": "function",
          "function": {
            "name": "get_weather",
            "arguments": "{\"city\": \"Beijing\"}"
          }
        }]
      }
    }]
  }
  关键信号：tool_calls 数组非空 + content 为 null。

  Gemini 格式（GeminiResponseParser）

  {
    "candidates": [{
      "content": {
        "parts": [
          {"text": "Let me check the weather."},
          {"functionCall": {"name": "get_weather", "args": {"city": "Beijing"}}}
        ]
      }
    }]
  }
  关键信号：parts 中出现 functionCall 类型的 part。

  两种格式都被解析器转化为统一的 ToolUseBlock：

  | ToolUseBlock 字段 | 含义                          |
  |-----------------|-----------------------------|
  | id              | 工具调用唯一 ID（来自厂商或框架生成）        |
  | name            | 工具名（如 get_weather）          |
  | input           | 工具参数（如 {"city": "Beijing"}） |
  | state           | 默认 PENDING，等待执行             |

  框架如何判断"模型想用工具"

  判断逻辑非常简单，在 isFinished() 方法中（ReActAgent.java:2059）：

  private boolean isFinished(Msg msg) {
      List<ToolUseBlock> toolCalls = msg.getContentBlocks(ToolUseBlock.class);
      return toolCalls.isEmpty();  // 空 = 结束；非空 = 继续执行工具
  }

  就一行判断：从 assistant 消息中提取所有 ToolUseBlock，如果有任何一个是空列表则循环终止，否则进入 acting 阶段。

  注意一个设计细节（line 2066-2068 的注释）：
  即使是不存在的工具调用也不会在这里拦截，而是放行到 acting 阶段，由 ToolExecutor 返回 "Tool not found" 错误，让模型自己看到错误并修正决策。

  数据结构层次

  ContentBlock  (sealed 接口，Jackson 多态序列化)
    ├─ TextBlock        → 纯文本（如 "答案是42"）
    ├─ ThinkingBlock   → 思维链中间态
    ├─ ToolUseBlock     → 模型请求调用工具  ← 判断标志
    ├─ ToolResultBlock  → 工具执行结果
    └─ ...

  消息中可以混合多种 block，例如一个 assistant 消息同时包含 TextBlock("让我查一下") + ToolUseBlock(name=get_weather)。
